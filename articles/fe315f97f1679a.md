# はじめに
ポートフォリオで作成したアプリについて、リビジョンというgitのコミットIDのようなものに名前をつけて管理(latest tag)していますが、ロールバック時に
- CloudRunのリビジョン保持期限
- 特定バージョンへのロールバックが不可能(latest tagのみを利用する場合)
という問題があり、これを解決すべく現状を整理するため記事にしました。

latest(最新)しかタグがないのでいざどこかでデプロイにミスが見つかっても過去のバージョンに遡れないという状況でポートフォリオを進めていました。
今まで何事もなくデプロイできててよかった(よくない)。



# 基本知識
備忘録として知識のおさらいをしておきます。
## CloudRunとその周辺技術
### CloudRunとは？
Dockerコンテナを置くだけでサーバーなしで自動スケールするバックエンドを作れるサービス(GCP)
AWSにはAppRunnerという競合も存在します。

Artifact Registryは、GCPのコンテナイメージやnpmなどのパッケージを管理するツールです。CloudRunとセットで使うのが標準構成です。


## ロールバックに関する知識
- latest tag を利用する
これは下記のrevisionsにタグを付与する機能で、最新のものに名前をつけます。
名前は自由につけられます。

Artifact Registryではデプロイ履歴(revisions)にタグをつけることができます。

- リビジョン形式
```
# サービス名-xxxxxx
myapi-00002-def
```

- タグ
```bash
# 1. タグ付きリビジョンをデプロイ（トラフィック流さない）
gcloud run deploy sample --image=... --tag=dev --no-traffic # dev タグ付与

# 2. タグURLで直接確認
https://dev---sample-xxx.a.run.app  → devリビジョンのみ表示

# 3. 良ければ本番トラフィックへ（ロールバックもこれ）
gcloud run services update-traffic sample --to-tags=dev=100 # dev 100%
```

### ロールバック
- リビジョン指定
```bash
# 過去リビジョンを確認
gcloud run revisions list --service=SERVICE --region=REGION

# 特定リビジョンに100%トラフィック移行（ロールバック）
gcloud run services update-traffic SERVICE \
  --to-revisions=REVISION_NAME=100 \
  --region=REGION
```

- タグ
```bash
gcloud run services update-traffic SERVICE \
  --to-tags=live=stable-revision \
  --region=REGION
```



# 改善方法

## 現在の構成と解決策
- 現在はCloudRunのイメージタグしかないものをGit履歴と紐づけることによって素早くロールバックできるように改善する
```
GitHub (main push)
    ↓
GitHub Actions (pytest)
    ↓
Cloud Build (docker build)
    ↓
Artifact Registry (latest tag のみ)  ← 問題点 # 解決策: Git履歴とイメージタグの紐付け $SHORT_SHA tag
    ↓
Cloud Run (k-back service)
```
